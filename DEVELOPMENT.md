# Development

The autogenerated artifacts under `docs/` and `outputs/` are checked
into the repo so they show up at a glance on GitHub. Anything that
edits source under `problems/`, `generator/`, `capabilities/`, or
adjusts the generator scripts has to **regenerate the docs and commit
the result** — CI ([`.github/workflows/check-docs.yml`](./.github/workflows/check-docs.yml))
fails any PR whose committed `docs/` don't match a clean regeneration.

## One-shot setup

The toolchain (Dafny 4.11, Agda 2.8, Idris2 0.8, Node 22) is pinned via
[`flake.nix`](./flake.nix) + [`flake.lock`](./flake.lock). Everything
runs inside a `nix develop` shell:

```sh
nix develop                  # drops you in a shell with all tools on PATH
npm install                  # bignumber.js, ses, @endo/bundle-source, @endo/import-bundle
```

After that, `dafny`, `agda`, `idris2`, and `node` are all available
as bare commands.

## The check loop

When you touch a verified source file or a generator script:

```sh
npm run check
```

This runs the full pipeline (build → ses → ffi → bundle → report) and
then `git diff --exit-code -- docs/`. Two outcomes:

- **Exit 0** — the committed `docs/` already match what the pipeline
  produces. Nothing to commit.
- **Exit 1** — the docs would change. Inspect with `git diff docs/`,
  commit the regenerated files alongside your source change, and
  re-run `npm run check` to confirm.

The same script runs in CI on every push and pull request, so a green
local check ≈ green CI.

## Individual scripts

```sh
npm run build      # compile + run every (problem × tool) cell
npm run ses        # static scan + lockdown()+require() + Compartment.evaluate() probes
npm run ffi        # call each tool's `sort` from external JS
npm run bundle     # @endo/bundle-source + @endo/import-bundle into a Compartment
npm run report     # render docs/<problem>.md from outputs/*.json
npm run all        # everything in order
npm run check      # npm run all && git diff --exit-code -- docs/
```

Outputs go to:

- `outputs/<problem>/results.json` — build + run + SES per cell
- `outputs/bundles.json` — bundle + import-bundle per cell
- `outputs/ffi-probe.json` — FFI per cell
- `outputs/bundles/<problem>/<tool>/` — preprocessed bundle inputs

## Adding a new problem

1. Create `problems/<problem-id>/{dafny,agda,idris2}/` with one source
   file per language.
2. Register it in [`generator/problems.js`](./generator/problems.js) by
   appending an entry to `PROBLEMS` (use `dafny(...)`, `agda(...)`,
   `idris2(...)` helpers).
3. If you want the SES bundle pipeline to cover it, also add an entry
   to the `TASKS` array in [`generator/bundle.mjs`](./generator/bundle.mjs).
4. Run `npm run check` — the failure surface is `docs/<problem-id>.md`
   not existing yet; the second pass after re-running creates it and
   passes.

## Why this exists

The whole repo is a comparison artifact. If `docs/` drift from the
sources, the comparison stops being trustworthy. The check script and
CI gate are the cheapest way to keep that invariant — they cost ~30 s
per PR after warm cache and catch the entire class of "I edited a `.dfy`
and forgot to commit the regenerated bytes table."
